Identity & Caching Infrastructure

By Rahul Shinde • 6 min read • Infrastructure & Security

In a microservices mesh with hundreds of distinct services, authorizing every incoming request against a centralized auth service creates an immediate bottleneck. Here is how we engineered a multi-region identity cache to achieve sub-millisecond auth lookups.

1. L1 Local Memory + L2 Redis Cluster Topology

By pairing an in-process local cache (with 2-second TTL) alongside a regional Redis cluster, 94% of authentication token verifications complete without leaving application process memory. 

// Two-Tier Auth Cache Fetch
func GetSession(ctx context.Context, tokenHash string) (*AuthClaims, error) {
    // Tier 1: In-Memory L1 Cache
    if claims, found := localLRU.Get(tokenHash); found {
        return claims.(*AuthClaims), nil
    }
    
    // Tier 2: Regional Redis L2 Cache
    claimsStr, err := redisClient.Get(ctx, "auth:" + tokenHash).Result()
    if err == nil {
        claims := parseClaims(claimsStr)
        localLRU.Set(tokenHash, claims, 2*time.Second)
        return claims, nil
    }
    
    // Fallback: Primary Auth DB
    return fetchFromDB(ctx, tokenHash)
}

2. Elasticsearch-Backed PII Identity Store with Key-Scoped Hashing

The canonical identity record store was built on Elasticsearch — optimized for fast lookup of identity tokens and hashed PII fields across multi-tenant datasets. Rather than storing raw PII, every sensitive field (email, phone, SSN) was hashed using a user-supplied or user-specific symmetric key. This meant:

  • Each user's PII was hashed with a unique derived key — preventing cross-user correlation even if the index was exposed.
  • Operators could supply their own tenant-level key for BYOK (Bring Your Own Key) compliance requirements.
  • "Forgetting" a user required only key destruction — all indexed Elasticsearch documents became mathematically unrecoverable without re-indexing.
// PII Field Hashing with User-Specific Key
func HashPIIField(rawValue string, userKey []byte) (string, error) {
    mac := hmac.New(sha256.New, userKey)
    mac.Write([]byte(rawValue))
    return base64.StdEncoding.EncodeToString(mac.Sum(nil)), nil
}

// Elasticsearch index doc — no raw PII stored
type IdentityDoc struct {
    UserID    string `json:"user_id"`
    EmailHash string `json:"email_hash"` // HMAC-SHA256 with user-specific key
    PhoneHash string `json:"phone_hash"`
    KeyRef    string `json:"key_ref"`    // Reference to KMS key ID
}

3. Dynamic Cache Invalidation via Bloom Filters

When a user logs out or updates their security credentials, invalidating local and multi-region caches instantaneously without flooding cross-region network links was solved by broadcasting bloom-filter invalidation pulses (Patented US11847291B2).

"Combining micro-TTL local caching with bloom-filter broadcast invalidation dropped overall API gateway p99 tail latency by 43ms."
